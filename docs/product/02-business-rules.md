## 1. 参与者与业务对象

| 对象 | 业务含义 | 权威来源 |
| --- | --- | --- |
| 访客 | 尚未建立有效身份与授权快照，只能进入公开认证流程 | 认证服务与公开路由契约 |
| 当前用户 | 已建立会话的操作者，不因浏览器保存了 Token 就自动获得权限 | 登录或 `/auth/me` 返回的身份 |
| 角色 | 权限与数据范围的分配载体；角色名称本身不等于权限 | 后端授权政策 |
| 授权快照 | 当前主体的有效授权、政策版本和数据范围 | 认证后端原子返回 |
| 菜单节点 | 导航目录、内部页面、外链或 iframe 的配置记录 | 菜单管理接口与前端注册表 |
| 页面实例 | 一个可恢复的工作上下文，包含 Tab 身份和允许保留的界面状态 | 路由元数据与当前会话 |
| 服务端记录 | 用户、角色、菜单等业务实体；状态以服务端确认结果为准 | 相应业务 API |

## 2. 认证、恢复与会话

### 2.1 登录入口

**AUTH-01 — 认证页与后台页分离。** 登录、找回密码、重置密码和可选注册是独立流程节点，不出现在常驻后台菜单。认证页不继承后台 Sidebar、Breadcrumb 或 Tabs。

**AUTH-02 — 登录标识。** 已确认目标支持用户名或邮箱；手机号登录不是 V1 核心承诺。字段为空、格式不符合所选标识类型时可就近提示；账号是否存在只能由后端处理。

**AUTH-03 — 中性凭据错误。** 未知账号和错误密码使用相同的公开失败语义，例如“账号或密码不正确”。不能为了区分字段错误而泄露账号存在性，也不能把内部错误、SQL 或身份提供方原始信息展示给访客。

**AUTH-04 — 登录提交。** 一次提交进入 Pending 后，按钮和提交处理器均阻止重复请求；保留账号输入与统一密码控件几何。网络失败不计入前端自行维护的“密码错误次数”，重试仍由当前表单发起。

**AUTH-05 — 验证码策略。** 提供 Provider 无关的验证码插槽，项目可选择 `always / adaptive / off`；是否需要挑战、挑战是否失效由后端政策决定。新挑战清除旧答案，不能继续提交已消耗的挑战。

**AUTH-06 — 锁定与限流。** 是否锁定、何时解锁、剩余尝试次数和 `retryAfter` 采用后端权威返回。模板不统一承诺“失败几次锁定几秒”；本地倒计时仅展示服务端政策，不替代分布式限流。

**AUTH-07 — 成功后的原子身份。** 登录成功必须取得用户、主体归属和授权快照，再加载授权导航。只拿到 Token、用户字段或角色名称中的一部分，不能进入“已认证且可操作”的状态。

**AUTH-08 — 回到目标页面。** 成功后优先恢复合法、站内且当前仍有权限的目标路径；没有有效目标时进入 Dashboard。外部 URL、认证循环路径或已失效目标不能直接作为登录重定向地址。

### 2.2 可选注册与密码恢复

**AUTH-09 — 注册默认关闭。** 注册能力由项目配置整体启用；关闭时不展示入口，也不能通过直接输入 URL 绕过开关。打开开关只代表流程被提供，不自动授予后台角色或管理权限。

**AUTH-10 — 注册后续政策。** 邮箱验证、人工审核、初始角色、是否自动登录和重名处理由接入后端契约确定；这些事项当前没有统一产品承诺。前端按契约呈现状态，不能自行选择高权限默认角色。

**AUTH-11 — 找回密码中性结果。** 已注册与未注册地址均返回相同的受理反馈，例如“如果该账号可恢复，我们将发送后续指引”。重发间隔和发送次数由服务端控制，不能借响应文案、返回结构或列表提示枚举用户。

**AUTH-12 — 重置凭证。** 重置 Token 为服务端生成、短期、一次性凭证。页面捕获后尽早移除可见 URL 中的敏感凭证；无效、过期或已使用时展示可恢复状态，允许重新发起找回流程。

**AUTH-13 — 密码政策。** 新密码、确认密码和修改密码遵守后端发布的同一政策；确认密码不匹配可本地检查。长度、字符组合、历史密码、到期时间和强制改密规则属于后端契约 / 待确认，不把现有组件常量定义为生产标准。

**AUTH-14 — 恢复完成。** 重置成功明确告知结果并提供登录入口；是否撤销其他会话、是否要求重新认证由后端执行并返回。前端不凭重置成功直接构造新的登录身份。

### 2.3 Token、退出和身份变化

**AUTH-15 — Access Token 可配置存储。** 已确认目标支持 `sessionStorage` 与 `localStorage` 两种策略，默认采用标签页会话策略，由项目配置选择。前者通常不跨新标签页共享，后者可跨浏览器重启保留；存储位置不决定后端会话是否有效，也不意味着“只能登录一次”。

**AUTH-16 — Refresh Token 边界。** Refresh Token 不暴露给 JavaScript；生产续期由后端管理 `Secure`、`HttpOnly` Cookie 及轮换。前端不得把“双 Token”理解为两者都必须放进 `localStorage`，也不得把浏览器存储模式误当成续期协议。

**AUTH-17 — 恢复必须重验。** 刷新页面时，即使存在本地 Access Token，也要重新取得有效身份与授权快照。过期、结构异常或被撤销的会话不恢复受保护内容；浏览器存储不可用时必须遵循明确降级或失败策略，不能残留半套凭据。

**AUTH-18 — 认证错误分级。** 401 按会话失效处理；普通授权 403 保留会话并提示缺少权限。`ACCOUNT_SUSPENDED`、`ACCOUNT_DISABLED`、`SESSION_REVOKED` 等明确终止性代码，即便 HTTP 状态为 403，也触发会话清理。

**AUTH-19 — 统一会话清理。** 退出、终止性失效、账号变化或后端确认的主体归属变化时，清理授权快照、动态路由、受保护 Query Cache、相关 Tabs/KeepAlive 和实时连接。旧请求的迟到结果不得重新写入新主体的界面。

**AUTH-20 — 持久化信息最小化。** Token 不进入 URL、日志、截图诊断或表单草稿；接口响应不随 Tabs 持久化。布局偏好与凭据分开管理，退出清理目录会话状态，但可保留按用户隔离的栏宽偏好。

**AUTH-21 — 续期接入验收。** Cookie 属性、跨站策略、CSRF、轮换、撤销和并发续期行为必须由接入后端及部署共同验证。当前文档没有承诺一套已工作的浏览器 Refresh Token 自动续期流程。

## 3. 角色、权限与数据范围

<!-- AI modified: 纳入本轮完整确认的 Permission 决策，替换此前尚未确认的多角色政策并澄清受保护授权边界。 -->

本节为 Q1070–Q1146 已确认目标；原型与运行时能力分别验收。示例角色为 Super Admin、Standard Admin、Operations Manager、Auditor、Content Editor，另以 Support Agent 展示停用状态；正常授权场景以 Operations Manager 为主。

### 3.1 权限的授予与生效

**PERM-01 — 角色分配权限。** V1 采用纯 RBAC，用户可拥有多个角色；启用角色的 Allow 取并集，没有 Allow 即拒绝，不提供 Deny、用户级权限覆盖或角色继承。权限编辑集中在 Role Drawer，不设独立 Permission Management 页面；复制角色用于复用配置。

**PERM-02 — 稳定授权标识。** 后端返回稳定业务权限标识及其前端 action/subject 投影。前端不得根据 `admin`、`editor` 等角色名称猜测授权，角色名称或页面标题变化不应改变权限标识。

**PERM-03 — 浏览器只决定体验。** 前端守卫、指令与 CASL 用于控制可见性和交互；每个受保护 API 必须再次校验认证、操作权限和数据范围。隐藏按钮不等于接口安全。

**PERM-04 — 缺失时拒绝。** 授权快照缺失、结构不兼容、过期或政策版本失效时默认拒绝，不沿用无法证明有效的高权限配置。重新取得合法快照后才恢复对应操作。

**PERM-05 — 隐藏与禁用。** 完全无权的业务操作通常隐藏；具备权限但因 Pending、记录状态或业务前置条件暂不可执行时才禁用，并说明原因。不能用禁用控件替代权限过滤。

**PERM-06 — 授权变更的草稿边界。** 在角色编辑中勾选权限仅改变草稿；保存成功才更新政策。取消或保存失败保留原有效权限，不在请求完成前更新当前登录用户的能力。

**PERM-07 — 授权变更生效。** 保存当前用户拥有的角色后重新获取 `/auth/me` 等权威身份快照，再重新计算导航、操作与缓存；其他在线用户通过请求或推送发现授权版本变化后执行同一刷新。后端撤权不等待前端刷新生效，旧快照不得继续通过接口校验。角色保存响应不能直接授予浏览器权限。

**PERM-08 — 失效页面回退。** 当前页面因菜单停用、删除或权限收回失效时，清理失效的 Tab/缓存并进入安全页面；主动访问已知但无权限路由展示 403。具体采用“Dashboard，若不可访问则首个合法页面”的回退顺序为本次细化建议 / 待评审；现有原型书面规则只记载失效页应回退，未明确该顺序。

**PERM-09 — 系统角色与自我失权。** 内置角色仅允许修改显示名称与说明，编码、状态、权限、数据范围和删除锁定；Super Admin 使用后端控制的只读超级权限标记，覆盖当前与未来权限，不以角色名称判断。普通管理员可编辑自己拥有的角色，可能失去管理能力时保存前警告，成功后刷新授权并进入仍可访问页面。既有管理恢复保护仍由后端执行，不因前端确认而解除。

### 3.2 数据范围

| 规则 | 范围 | 业务含义 |
| --- | --- | --- |
| PERM-10 | 本人 | 只能访问当前主体拥有或被定义为本人的记录，归属字段由领域契约决定 |
| PERM-11 | 本部门 | 只访问当前有效部门范围；部门缺失不能扩大为全量 |
| PERM-12 | 本部门及下级 | 依据权威部门层级计算，不把浏览器传入的显示路径当成授权凭证 |
| PERM-13 | 自定义部门 | 只采用允许选择且仍存在的部门 ID；空集合不等于全部部门 |
| PERM-14 | 全部数据 | 仅在后端明确授予时生效，仍受租户和其他后端边界约束 |

**PERM-15 — 先授权后查询。** 数据范围在筛选、排序、分页和汇总前执行；列表数量、搜索命中数、导出与详情查询均不能越过同一范围。不能先获取全量记录再仅在浏览器隐藏部分行。

**PERM-16 — 操作权与敏感字段。** 能查看用户不代表能修改用户；能创建用户不代表能分配角色。邮箱等敏感字段按能力投影或脱敏，搜索、导出与总数也应避免反向泄露被隐藏字段。

**PERM-17 — 多角色范围合成。** V1 使用角色级默认数据范围，预留资源级扩展；只作用于声明支持数据范围的资源与操作。同一资源/操作的范围取实际授予该操作的启用角色的并集；其中任一角色为“全部”才得到该资源/操作的全部数据。不得先合并所有角色范围再套用到所有操作。例如角色 A 可编辑本部门用户，角色 B 只能查看全部用户，则最终可查看全部、仅可编辑本部门。跨部门调动后的重算及跨租户边界由后端契约执行，角色并集不能突破租户边界。

**PERM-18 — 自定义部门语义。** 使用可搜索、多选且有半选状态的部门树，并提供“包含所选部门的下级部门”开关；开启后动态包含现有及未来新增下级，关闭后只包含明确选择的部门。摘要说明这一行为；无可用部门或空集合不能回退为全部数据。

### 3.3 功能权限树与可授予边界

**PERM-19 — 页面访问与目录批选。** 页面节点授予访问权，菜单由已授权页面和导航配置生成；隐藏页面可以授权但不出现在菜单。目录三态 Checkbox 表示对子树的批量操作，页面访问 Checkbox 只表示访问，不自动全选按钮。勾选操作保留其页面访问及祖先路径；取消页面清除其可修改操作。若锁定后代要求页面访问，保留必要依赖并解释，不能借父级取消修改锁定权限。

**PERM-20 — 搜索与批量修改。** 搜索保留命中节点及完整祖先，只负责过滤和定位，不另建临时选中集，也不提供跨搜索结果的选择或清除操作。展开与收起全部使用一个随当前状态变化的控件。批选收敛到模块级，仅修改该模块中可修改的页面和操作；依赖祖先可以补齐，但不能扩大到其他模块或隐藏项。模块批选前后均保持页面访问与操作授权的独立语义，锁定或隐藏项不计入可修改数量；服务端摘要不得通过差额泄露隐藏权限。

**PERM-21 — 授权目录与锁定项。** 后端分别提供可修改权限、可公开但不可修改的只读权限，完全隐藏项不下发。只读权限保留原树位置、勾选状态和“无权变更”原因；客户端不推定操作者当前拥有的权限等于可授予范围。加载完整的可查看目录，搜索在本地完成，可见节点超过配置阈值后虚拟化；初次展开含已选权限的祖先，其余收起，本次 Drawer 会话记住展开状态。

**PERM-22 — 未知权限与空目录。** 快照中的旧权限编码在授权可见边界内以“异常授权项”只读展示，普通保存不静默删除；清理由明确迁移或审计流程完成。无可授予权限但有可查看内容时保留只读锁定树；没有可展示目录才显示 Forbidden 与说明，仍可按权限编辑基本信息。角色没有任何功能权限可以保存，但须提示其不会赋予功能访问权。

### 3.4 角色生命周期与用户关联

**PERM-23 — 列表与基本信息。** Role 页面使用 SearchForm + DataTable，筛选为关键词、角色类型、状态；列表展示名称、编码、类型、状态、用户数、页面/操作数与数据范围摘要、更新时间、操作。内置角色置顶，自定义角色按更新时间倒序。基本信息字段为名称、编码、类型、状态、说明；编码以小写字母开头，允许数字、`-`、`_`、`:`，全局唯一且创建后只读。创建产生自定义角色，系统类型不是提升权限的可选字段。

**PERM-24 — 停用与删除。** 自定义角色逐项查看、编辑、复制、启用/停用、删除，V1 不提供批量权限修改、停用或删除。停用成功即不参与授权，保留用户关联；确认说明关联用户数、权限范围及生效方式，多角色下关联人数不等于必然失权人数。有用户关联时禁止删除，先转移或解除关联；允许删除时确认名称、编码和不可恢复后果，不要求输入名称。

**PERM-25 — 复制角色。** 打开 Create Role Drawer 供检查配置，名称带“副本”、编码留空并聚焦、默认启用，提交后才创建。复制后端允许授予的显式功能权限及数据范围，不复制用户关联、系统角色类型或超级权限标记；源配置不可授予时明确锁定/受限原因，不能由复制绕过授权边界。

**PERM-26 — 用户分配角色。** User Drawer 是关联关系唯一编辑入口，采用可搜索多选；角色选项展示类型、状态、简短权限摘要。已分配停用角色保留并标记“未生效”，不可新增选择，但有角色分配权的操作者可从已选区独立移除。Role 列表用户数和只读详情中的关联用户入口跳到带角色筛选的 User Management Tab，不再嵌套用户编辑 Drawer。

**PERM-27 — 有效权限解释。** User Drawer 展示只读合并摘要及角色来源，按资源/操作解释页面、操作和数据范围贡献；未保存选择仅作草稿预览，服务端结果仍是权威。保存前说明新增/移除角色与有效范围变化。Role 名称或查看入口复用只读 Drawer，显示基本信息、功能权限、数据范围及关联用户摘要；创建/修改人和时间保留，完整历史只在已启用审计能力时跳转。

### 3.5 原子保存、冲突与错误恢复

**PERM-28 — 统一提交与隐藏保留。** 基本信息、功能权限和数据范围通过底部保存一并提交。客户端携带角色版本与目录版本，只提交可修改范围的草稿；后端重验可授予边界，在同一事务中保留锁定、隐藏及未清理的旧编码，形成完整原子快照。不能使用客户端可见树覆盖完整服务端权限，也不能让客户端伪造“锁定”字段取得保护或授予能力。

**PERM-29 — 差异与高影响确认。** 保存前展示允许查看的新增/移除权限、数据范围变化及影响说明；移除权限、缩小范围、停用等高影响变化用短确认 Dialog，Drawer 草稿保留。人数标明“关联用户”或后端实际计算的“受影响用户”，不把前者当作失权人数。确认不是授权凭据；提交时仍按最新权限和版本校验。

**PERM-30 — 三类版本。** 角色版本控制编辑并发，目录版本控制权限定义一致性，授权快照版本控制登录主体的有效权限。角色冲突保留草稿，允许查看最新版本、复制草稿或重新加载后人工处理；目录更新也保留草稿，保存前要求重读核对。两者均不静默覆盖、自动合并或强行重试；普通后台刷新不能重置编辑中的草稿。

**PERM-31 — 错误与关闭。** Shell 与 Tabs 首次即可打开，权限目录区域使用几何匹配 Skeleton。字段/节点错误定位对应 Tab 与控件，一般失败在 Footer 上方给可重试 Callout，保留草稿。所有关闭入口遵守 Dirty/Pending 保护；授权保存成功而随后快照刷新失败时分别说明结果，不能再次提交已成功的授权事务。

## 4. 菜单配置与动态路由

### 4.1 节点类型与身份

| 规则 | 类型 | 允许的业务职责 | 子级边界 |
| --- | --- | --- | --- |
| MENU-01 | 目录 | 组织导航层级；直接访问目录地址时才重定向。“进入首个已启用且有权限子页面”为本次细化建议 / 待评审 | 可包含合法目录、页面、外链或 iframe；具体父子类型矩阵待评审 |
| MENU-02 | 内部页面 | 映射白名单页面组件，参与 Breadcrumb、Tabs、搜索和缓存 | “仅可附加隐藏辅助页面”为本次细化建议 / 待评审 |
| MENU-03 | 外链 | 打开符合允许策略的外部地址，并明确新窗口行为 | 叶子节点 |
| MENU-04 | iframe | 在内部路由页面嵌入允许的目标地址；默认不启用 KeepAlive 为本次细化建议 / 待评审 | 叶子节点 |

来源界限：原型计划明确四类编辑流程、隐藏辅助页和目录点击/URL 访问的区别，但未写明上述父子类型矩阵、目录首项重定向顺序或 iframe 默认缓存值；不能用缺少原题的历史选择补足这些确认记录。

**MENU-05 — 稳定 routeKey。** 页面拥有生成后不可编辑的稳定路由身份；名称、路径和组件可按权限修改，但不能借改名制造新的缓存/Tab 身份。`routeKey`、菜单记录 ID、URL 与组件键职责不同，不混用。

**MENU-06 — 白名单组件。** 后端只能返回约定 `componentKey` 和图标键，前端通过固定注册表解析。未知键不能作为动态 import 路径或可执行表达式；隔离非法配置并向管理员提供可修复原因。

**MENU-07 — 层级与信息架构。** 工作概览为一级页面，系统管理、运营、示例中心为目录；正式导航保持三级以内，四级以上仅作示例中心能力 Demo。显示层级变化不自动改变既有 URL。

**MENU-08 — 可见性不是可用性。** `menuVisible=false` 只隐藏菜单入口，仍可保留有权访问的路由、Breadcrumb、搜索或 Tab；`enabled=false` 则使节点运行能力失效。隐藏页面不能被当成已停用页面。

**MENU-09 — 父级停用。** 父目录停用后后代运行时均失效，但保留每个后代自身开关值。重新启用父级后重新计算有效状态，不能把原本关闭的子级一并开启。

**MENU-10 — 页面行为开关。** 隐藏、停用与父级有效状态的区别已有书面确认；进一步将菜单可见、搜索收录、Breadcrumb、Tabs 和 KeepAlive 全部设计为节点级独立开关，是本次细化建议 / 待评审。建议保留自身配置，并单独展示继承后的有效状态；待确认各开关允许组合及默认值。

**MENU-11 — 动态参数页面。** 隐藏辅助页面可有动态参数，并通过 `activeMenu` 激活所属可见菜单；缺少合法参数时不能生成可点击搜索结果，这两点有原型书面记录。进一步限制“可见导航只使用静态路径”为本次细化建议 / 待评审；确认前只要求可点击入口能够解析为合法目标。

### 4.2 编辑、校验与生效

**MENU-12 — 编辑入口。** 目录、页面、外链和 iframe 均使用 BusinessDrawer；新增和编辑不单独设置发布步骤。输入阶段提供只读、尚未保存的路径、Breadcrumb、菜单、Tab、缓存与有效状态预览。

**MENU-13 — 结构校验。** 保存前检查重复路径、保留路径、非法参数、父子类型冲突、环引用及无效父级。错误指向字段或冲突节点；后端必须重复校验，不能因前端预览合法就直接接受。

**MENU-14 — 排序与移动。** V1 不提供菜单拖拽或批量修改，来源为原型计划 `07B`。使用排序值、上移/下移和父级字段作为具体调整入口，以及移动后展示完整位置预览，为本次细化建议 / 待评审；原书面记录只有排序列与行操作菜单，未明确这组操作。

**MENU-15 — 删除约束。** 含子节点的目录不能直接删除，不进行隐式级联；先移动或处理子级再删除。确认界面说明目标，取消不发起请求；后端在提交时再次检查引用关系。

**MENU-16 — 保存立即生效。** 保存成功后刷新菜单管理列表并更新当前导航投影。失败时保留输入；若保存成功但导航刷新失败，应明确区分两个结果并提供刷新恢复，避免用户误以为需要重复创建。

**MENU-17 — 当前页面变化。** 菜单变更后应刷新导航，失效当前页执行 PERM-08 的安全回退。名称/图标变更时原位更新 Tab、当前路径修改后使用替换导航的具体处理方式，为本次细化建议 / 待评审；现有书面记录未明确路径变更后的浏览器历史策略。

**MENU-18 — 后台刷新。** 初次导航未取得时可显示导航 Skeleton 与重试；已有合法导航时后台刷新保留旧树，成功后整体替换。不得先清空菜单再逐个注册，造成短暂空白或权限闪现。

### 4.3 外部目标与异常边界

**MENU-19 — 外链策略。** 外部目标使用 HTTPS 和明确来源策略，禁止携带 URL 用户名/密码或可执行协议；新窗口具备安全关系属性。原型中的示例域名不是自动批准的部署域名。

**MENU-20 — iframe 双重允许。** 前端允许列表、后端策略、sandbox 和部署 CSP 必须共同允许目标。第三方拒绝嵌入时保留 Shell，提供局部重试或在策略允许时外部打开，不把整个后台变为不可用。

**MENU-21 — 跨域失败措辞。** 浏览器无法可靠区分所有跨域服务故障。只展示可验证的阻断原因，否则使用“内容暂时无法加载”等中性提示，不能编造第三方服务内部故障。

**MENU-22 — 路由错误分类。** 已知但无权路由为 403，未知路由为 404，页面组件加载失败进入页面级 500 边界；其他合法 Tab 和 Shell 继续可用。真正的应用根级致命错误采用整体恢复界面，不能与局部页面错误混为一谈。

**MENU-23 — 无可访问页面。** 权限过滤后没有任何业务入口时，保留最小 Shell 与中性状态，提供联系管理员等恢复说明；不循环跳转、不自动退出，也不把空导航等同于后端加载错误。

## 5. Sidebar、搜索、Tabs 与页面缓存

### 5.1 导航行为

**NAV-01 — 目录和叶子分工。** Sidebar 点击目录整行只展开/收起，允许多个目录同时展开；页面叶子点击导航。目录 URL 的重定向只发生在访问该 URL 时，不能让一次展开操作同时切换页面。

**NAV-02 — 激活定位。** 当前叶子与祖先具有不同的选中层级；当前页面变化时自动展开祖先并将激活项滚入可视区域。隐藏页面使用 `activeMenu`，不临时插入菜单树。

**NAV-03 — 空目录过滤。** 无任何可访问后代的目录整体隐藏；权限变化后重新计算。隐藏空目录只影响导航，不应误删管理端仍需修复的菜单配置记录。

**NAV-04 — 三类 Layout 的状态。** Sidebar、Top 和 Mixed 共享授权树、当前路由与 `activeMenu`。栏宽偏好存入 localStorage、目录状态存入 sessionStorage，均按用户及 Layout 隔离；同一 Layout 的 Sidebar、Rail 和移动 Drawer 共享目录状态。

**NAV-05 — 收缩与移动。** 收缩态叶子直接导航，目录在一个 Flyout 中展示嵌套树；移动端采用导航 Drawer。移动点击页面后关闭 Drawer，展开目录不关闭，再次打开保留本次会话展开状态。尺寸与键盘细则见 [UI 与交互](./04-ui-and-interaction.md)。

### 5.2 页面搜索

**NAV-06 — 搜索范围。** V1 搜索有权限的页面，不承诺跨用户记录、审计数据或全站内容搜索。候选来自同一份路由元数据，也可收录允许搜索的隐藏页面。

**NAV-07 — 结果排序（本次细化建议 / 待评审）。** 建议空关键词展示授权范围内的最近访问和常用页面；有关键词时按名称、路径、关键词相关性并结合最近访问排序。中英文按当前语言呈现，结果说明所属层级。原型计划确认了页面搜索及权限范围，但未记录上述空词内容与排名策略；权重、常用来源和历史清理规则仍待评审。

**NAV-08 — 结果再校验。** 选择结果前重新确认路由可用性、权限和动态参数。停用、已删除、权限撤回或参数缺失的历史结果不可继续打开；无结果显示搜索空状态并允许修改关键词。

### 5.3 Tabs 与 KeepAlive

**NAV-09 — Tab 身份。** Dashboard Tab 固定，普通业务 Tab 使用稳定页面实例身份。仅修改当前页筛选 query 时更新该 Tab 的地址，不为每次搜索创建一个同名 Tab；业务明确打开独立实例时才增加新的实例身份。

**NAV-10 — 关闭顺序。** 固定 Dashboard Tab 和 Dirty/Pending 保护保留确认基线。补充“关闭其他/右侧”操作集合及“关闭活动页后优先右邻、否则左邻”的顺序为本次细化建议 / 待评审；原型计划的 `07A` 仅记载 Tabs 操作场景，未展开这些选项和顺序。

**NAV-11 — 刷新恢复。** Tabs 默认使用 sessionStorage，可由项目配置启用持久存储。仅记录合法页面身份和必要 UI 状态；恢复时重新校验当前身份、路由与权限，服务端数据重新查询。

**NAV-12 — KeepAlive 默认边界。** 默认 LRU 上限为 10，可配置；保存组件实例以恢复筛选、展开和滚动等界面上下文，不把 API 响应当成可持久化缓存。未启用缓存的页不因存在 Tab 就自动缓存。

**NAV-13 — 缓存淘汰。** 关闭 Tab 时淘汰对应实例；超过上限时淘汰最久未访问实例。退出、身份变化和权限收回清理对应缓存；被淘汰后再打开按正常首次加载规则执行。

**NAV-14 — 保留实例不等于持续工作。** 页面停用或隐藏时，按业务规则暂停轮询、实时连接、观察器等资源。恢复页面时根据数据新鲜度刷新，不能因为 KeepAlive 保留了 DOM 就继续无界后台请求。

**NAV-15 — URL 允许列表。** 可分享筛选、分页、排序和详情 ID 只接受已声明值；移除未知值、默认值和重复歧义参数，并保留不属于当前控件的合法 query。浏览器前进/后退必须恢复可见控件及页面状态，不能只更新地址栏。

## 6. Dashboard 权限与异步生命周期

**DASH-01 — 默认工作入口。** Dashboard 是模板首页和组合能力示例，不绑定某一真实企业的经营指标。角色首页和上次访问入口仅保留扩展点，V1 默认仍为工作概览。

**DASH-02 — 模块按权限注册。** 根据身份和有效授权决定可见模块；无权模块不渲染、不注册 Query、不发请求，也不保留空白占位。剩余模块重新组织布局。

**DASH-03 — 数据与行为权限分开。** 可以看指标不代表可以打开其明细、处理待办或进入管理页。快捷入口、图表跳转、列表动作均单独遵守目标页面和操作权限。

**DASH-04 — 首次加载。** 只为已通过权限过滤的模块显示与内容几何匹配的 Skeleton；一部分模块完成不必等待其他模块。不得先显示无权模块 Skeleton 再隐藏。

**DASH-05 — 首次失败。** 某模块没有可用数据且请求失败时，在该模块显示错误与重试。其他模块和 Shell 保持可操作，不以全页 500 替代所有局部失败。

**DASH-06 — 后台刷新。** 已有数据时保留旧内容并显示轻量刷新状态；刷新期间不回到首次 Skeleton。重复刷新入口暂时抑制，数据成功返回后更新对应区域。

**DASH-07 — Stale 失败。** 后台刷新失败时保留旧内容，标明更新失败或数据时间并提供局部重试。不能把旧值标为最新，也不能让失败 Toast 成为唯一可恢复入口。

**DASH-08 — 成功空数据。** 成功返回空集合与请求失败分开；该模块显示主题化 Empty 插图及适用动作。零值指标是合法数据，不能把“用户总数为零”直接等同于所有 Dashboard 模块为空。

**DASH-09 — 无可见模块。** 授权后的模块 Registry 为空时，保留 Dashboard Shell 和透明背景中性状态，不发模块请求、不展示 Skeleton、不自动跳转 403。

**DASH-10 — 日期草稿与应用。** 日期面板编辑只影响草稿；应用后才更新全局范围并刷新受该范围影响的 KPI/图表。取消保留旧范围，待办、活动和健康模块可保有自己的时间语义。

**DASH-11 — 请求竞争。** 快速切换日期或模块条件时，取消可取消的旧请求，或确保迟到结果不能覆盖当前条件。Query 身份应包含影响结果的主体、权限或时间范围等必要上下文。

**DASH-12 — 权限运行中变化。** 收回权限时立即取消对应请求、移除模块和敏感缓存；新增权限后按首次加载进入。不能保留可查看的旧敏感数据直到下一次手动刷新。

**DASH-13 — 刷新与实时更新。** 手动刷新仅更新当前可见查询；轮询或实时事件按模块需要启用。隐藏、离线、身份变化及页面离开时暂停或释放相关资源，恢复后按契约补齐。

**DASH-14 — 数据口径。** 指标单位、比较区间、时区和更新时间应可理解；百分比基数为空时不能编造变化率。示例图表的展示数字不能被视为真实服务级别或产品性能保证。

## 7. 通用列表与 CRUD

### 7.1 列表入口与配置组合

**LIST-01 — 一个公开增强入口。** 业务列表默认使用统一 DataTable；高级能力通过配置和可选插件提供，不对业务开发者长期暴露两个职责重叠的 DataTable/ProTable 入口。既有 ProTable 属于迁移差异，不能写成最终产品架构。

**LIST-02 — 简单表格保持轻量。** 纯静态结构可直接使用语义 Table，不必加载 Vue Query 或 TanStack Table 运行成本。Local DataTable 与 Remote DataTable 的数据来源要明确，不能根据传入数组长度偷偷决定查询模式。

**LIST-03 — 组合而非强制捆绑。** SearchForm 管查询输入，DataTable 管列表展示与通用状态，FormDrawer 管编辑流程。`ListWorkspace` Shell 统一页面结构，`useListWorkspace` 协调已应用条件、URL、选择与 Drawer；各基础组件仍独立可用。通用组合不绑定业务 API，也不强制每个列表携带搜索、编辑、导入或批量操作。

**LIST-04 — 插件按需启用。** 虚拟滚动、树形、固定列、列设置、行内编辑等高级能力独立启用；配置冲突必须明确反馈或限制，不能显示没有实际效果的选项。具体组合能力以验收过的插件矩阵为准。

### 7.2 搜索、分页、排序与选择

<!-- AI modified: 将 09 阶段已确认的默认搜索与选择策略升级为目标规则，保留端点和运行验收边界。 -->

**LIST-05 — 查询草稿。** 默认将未提交输入与已应用条件分离，点击查询或在适用字段按 Enter 后应用并回到第一页；重置立即恢复默认条件并查询。即时查询由具体页面显式选择，可对适用字段启用防抖，不从输入变化自动推断。

**LIST-06 — 后端分页契约。** 接口页码从 1 开始，返回 `items / total / page / pageSize`；前端内部可从 0 开始，但只转换一次。Remote DataTable 默认每页 20 条，选项为 20/50/100/200；共享 API 单页上限为 200，具体端点可收紧。分页范围表达当前页实际数据范围，不等于内部滚动视口当前可见行数。

**LIST-07 — 排序字段允许列表。** 只提交后端支持的排序字段与方向；排序影响当前结果集时回到合法页并重新查询。显示名称不能直接成为数据库字段，也不能在服务端分页中只对当前页排序却伪装全量排序。

**LIST-08 — 条件与页码失效。** 搜索、页大小或有效数据范围变化时修正页码；删除最后一页全部记录后回到最近合法页。服务端返回总数变化不应让界面长期停留在一个不存在的页。

**LIST-09 — 保留旧列表。** 分页或筛选请求期间可以保留上一份数据并标明刷新状态，但行操作必须明确对应当前显示记录。新条件尚未完成时，不能把旧行误称为新条件结果。

**LIST-10 — 选择以稳定 ID 为准。** 行选择不能以排序后的索引或当前 DOM 位置为身份。默认页内选择，跨页保留由页面显式开启并展示已选数量和范围；页内全选不等于全量结果全选，后端再次验证每个目标。

**LIST-11 — 选择失效与恢复。** 筛选、排序、页大小变化或显式刷新默认清空选择；页内模式翻页时清空，明确开启的跨页模式才保留。批量结果区分成功、失败和未处理目标，重试不能再次提交已成功对象；超出默认策略的长期选择由业务 Recipe 显式约定。

**LIST-12 — 分页与虚拟滚动兼容。** 单页 200 条时可以启用虚拟滚动，两者分别解决数据请求量和渲染量。树形虚拟化先展开为可见行序列再渲染，折叠后正确更新可见行数、焦点与选择状态。

### 7.3 新增、编辑、删除与批量结果

**LIST-13 — 创建和编辑。** 根据授权展示新增/编辑入口，在 BusinessDrawer 中提交。服务端成功前不把草稿作为已保存记录；成功后默认关闭 Drawer，精确更新或失效受影响 Query，保留筛选和合法页码。新记录不在当前结果中时提供“查看新记录”，不清空条件、强制跳页或插入不匹配记录。“保存并继续”须由 Recipe 显式开启。

**LIST-14 — 详情读取。** Drawer 立即打开，远程详情未就绪时显示匹配结构 Skeleton；可信缓存可先展示并标记刷新，不把列表摘要当作完整详情，也不让迟到响应覆盖已改草稿。只读详情不自动授予编辑权，可通过白名单 URL 恢复；对象不存在或已无权时展示对应边界并清除不可继续访问的敏感内容。

**LIST-15 — 删除前置条件。** 删除需明确目标和后果，短确认使用 Dialog/AlertDialog。有关联子项、被引用或受保护记录时，应由后端拒绝并返回可理解原因；模板不默认提供级联删除或绕过引用检查。

**LIST-16 — 用户管理保护。** 用户 Demo 应保留不能删除当前操作者、不能移除最后一个启用管理员的保护；更新状态或角色也应遵守管理恢复路径。生产如何识别“最后管理员”、是否软删除及保留多久由后端契约决定。

**LIST-17 — 角色分配单独授权。** 创建/编辑用户不自动拥有角色分配权；无相应能力时只能按后端允许的默认角色创建，不能通过篡改表单或 CSV 提升角色。用户停用、删除时已有会话由后端撤销。

**LIST-18 — 批量操作的真实结果。** 批量请求区分全部成功、全部失败和部分成功；显示成功/失败数量与可定位目标。不能把 `Promise.all` 的一次失败解释为所有目标都未执行，也不能直接重试已成功的目标。

**LIST-19 — 重复提交与幂等。** Pending 期间防重复操作属于前端体验保护；导入、不可逆动作和高风险写入是否可重试，由后端幂等契约决定。网络超时后的结果未知不能自动当作失败并重发全部操作。

### 7.4 导入、导出与文件

**LIST-20 — 导入政策。** 上传前读取当前安全上传政策，并与端点业务限制取交集；政策加载失败或明确不允许目标类型时提供恢复说明。权限、类型或限制在选择后发生变化时，提交前再次校验。

**LIST-21 — 用户 CSV 契约。** 当前用户导入契约为 UTF-8 CSV、最多 256 KiB、200 数据行，固定 `name,email,role,status` 表头，可附加 `createdAt`；这些是该端点限制，不是所有上传组件的全局限制。接入后端变更时需同步契约与验收。

**LIST-22 — 行级错误。** 导入检查必填项、枚举、重复记录、角色授权和公式前缀，结果返回创建/跳过数量及行号原因。已成功行保留，失败明细可查看并用于修正；短暂 Toast 不能是唯一长期可用的错误记录。

**LIST-23 — 文件真实性。** 扩展名、浏览器 MIME 和文件名不是可信安全证明；后端重新检查字节数、内容签名、授权并生成安全存储名称。普通用户只能取得上传所需的安全政策，不取得对象存储密钥。

**LIST-24 — 导出范围。** 页面应明确“当前页、选中记录或筛选结果”的实际导出范围；没有后端全量导出能力时不能把当前页文件命名为全量结果。导出数据遵守相同权限、数据范围和敏感字段脱敏规则。

**LIST-25 — 导出格式与结果。** CSV 等可由表格软件打开的输出需防止公式注入；下载失败提供可恢复反馈，不能展示未完成文件的成功提示。大范围异步导出遵守 LIST-31；任务端点、下载有效期、次数与审计策略由接入后端约定。

### 7.5 工作区与增强 Recipe

**LIST-26 — URL 与个人偏好。** URL 默认同步已应用筛选、分页、页大小和排序，使用稳定白名单及序列化规则，省略空值和默认值；不包含草稿、已选行。高级筛选展开状态只在当前逻辑 Tab 会话中记忆。列显隐、顺序及密度按用户身份与稳定 Table ID 保存到本地偏好并可恢复默认，不进入分享 URL。

**LIST-27 — 空状态证据。** 只有权威信息确认当前有权数据集本身没有记录时才展示 First Use；已应用筛选无结果展示 Search Empty；明确访问拒绝展示 Forbidden。当前页 `items=[]` 或被筛选后的 `total=0` 不足以推断全库为空，也不把未知原因当作无权限。

**LIST-28 — 即时与行内编辑。** 只有低风险、可回滚的即时开关按配置启用乐观更新；常规新增、编辑、删除等待服务端成功。用户状态以 Badge 表达，通过明确操作变更，停用等高影响操作先确认。行内编辑作为插件显式进入，默认同时只编辑一行，保留保存与取消。

**LIST-29 — 用户列表动作。** 姓名链接打开详情，默认直接显示编辑，其余查看、分配角色、启停和删除进入 More；整行点击默认关闭。批量操作为启用、停用、导出所选和删除，按授权呈现；不默认提供批量角色分配。危险确认明确数量、范围和后果。

**LIST-30 — 导入任务闭环。** 可选导入 Recipe 使用上传、校验预览、结果三步；重复记录策略由后端能力决定，无更新能力时只能跳过并说明。成功行保留，结果包含行号、错误原因和错误文件下载；仅重试已修正的失败行。关闭 Drawer 后保留可重新打开的最近任务摘要。

**LIST-31 — 导出任务闭环。** 入口明确当前页、选中记录或筛选结果，字段来自后端允许的导出配置。当前页或少量所选可直接导出，大范围结果使用后端异步任务；当前页面提供持续状态，未来任务中心可接入，但不作为 V1 前置依赖。实际端点能力、文件有效期与审计政策仍须接入约定。

**LIST-32 — 09D Recipe 边界。** 09D 以可直接二次开发的高级操作 Recipe 为主，覆盖导入、导出、批量操作、单行编辑、树形表格和虚拟滚动；Demo 只负责验证这些能力。五组 Candidate 均属于可关闭的示例中心，不因示例场景改变核心信息架构。

**LIST-33 — 单入口与插件成本。** 业务增强保持唯一公开 `DataTable` 入口，高级能力通过按需插件接入，页面 Recipe 组合业务流程。不得为各能力建立互不兼容的平行表格组件，也不得让未启用高级能力的基础列表静态加载其运行成本。

**LIST-34 — 服务端权威与组合承诺。** 导入校验、全量导出、批量写入、权限、幂等和冲突判定以服务端为权威；前端负责流程、状态与结果呈现。仅承诺通过验收的插件组合，未验证组合必须标记为实验性或不支持，不能宣称任意组合可用。

**LIST-35 — 导入格式与确认。** CSV 是稳定导入基线，XLSX 通过可选适配器接入。业务示例优先使用版本化固定模板，通用 Recipe 可按配置增加字段映射步骤。浏览器预检不能替代服务端解析和权威校验；校验预览后必须由用户明确确认。重复项默认跳过，只有端点声明支持更新时才提供更新已有记录选项。

**LIST-36 — 导入任务与关闭。** 导入使用统一任务契约，允许服务端根据规模快速完成或异步执行。部分成功保留成功行，提供行级失败、错误文件及仅重试修正失败行的能力。上传和校验阶段可取消；提交后关闭 Drawer 不等于取消任务，页面保留可恢复摘要，取消入口只在服务端支持时出现。

**LIST-37 — 导出字段与授权。** 导出范围为当前页、已选记录或全部筛选结果；默认字段取当前可见列，但不得超出服务端允许清单。CSV 为默认格式，XLSX 可选。当前页或少量选择可以直接下载，全部筛选结果走异步任务；创建任务和下载文件时都重新校验身份、范围、字段权限和有效期。

**LIST-38 — 批量结果模式。** 每个批量端点必须声明原子或允许部分成功，前端根据响应展示逐项结果；不能以本地成功状态掩盖服务端失败，也不能假定所有领域共享同一种原子性。

**LIST-39 — 批量确认与恢复。** 高影响批量操作必须在 AlertDialog 中明确目标数量、实际范围和后果；完成后在页面保留结果摘要，并允许进入 Drawer 查看逐项结果。部分成功只能重试仍合法的失败目标，已成功目标不得重复执行。

**LIST-40 — 行编辑会话。** 商品价格与库存 Recipe 通过明确行操作进入编辑，默认同时只有一行。保存和取消始终可见；Enter/Esc 只在不改变输入控件原有语义时生效。切换行、分页、筛选或离开页面遇到脏行时，必须由用户选择保存、放弃或继续编辑。

**LIST-41 — 行编辑权威结果。** 价格和库存等待服务端成功后更新，只有低风险可回滚字段可配置乐观更新。写入携带记录版本；409 保留输入并提供差异及最新值。保存后按权威筛选和排序重新定位，记录离开当前结果时必须说明，不得将其固定在错误位置。

**LIST-42 — 树模式与选择。** Tree Table 显式选择 Local 完整树或 Remote 懒加载。父子选择默认独立；级联必须由业务开启，并定义半选、未加载后代和新增后代的范围。展开状态只在当前逻辑 Tab 会话内恢复，且过滤不存在或无权节点。

**LIST-43 — 树搜索、加载与排序。** 远程分支加载失败只影响当前节点并提供重试。搜索结果保留命中节点与祖先路径，但不修改真实展开或选择状态；排序只作用于同级兄弟，Remote 模式以服务端稳定层级顺序为准。

**LIST-44 — 虚拟事件流。** Virtual List 示例使用只读审计事件和 Cursor/Infinite Query，不叠加选择、批量或行编辑。接近末端时预取下一批，追加后保持滚动锚点，失败在末端局部恢复；离开顶部后到达的新事件以计数入口提示，不能强制改变阅读位置。

**LIST-45 — 09D 页面组合。** Import、Export & Batch、Inline Edit、Tree Table 使用完整示例中心 Shell，States 使用局部上下文。Import 从用户列表进入三步 Drawer；Export/Batch 从商品列表进入范围选择、确认、任务摘要和结果明细。任务流程由独立 Recipe 组合，不成为 DataTable 内部职责。

**LIST-46 — 商品行编辑字段。** 商品名称与 SKU 是只读身份字段；售价、库存、状态和仓库可按权限编辑。活动行必须明确标识编辑边界并保留保存、取消、字段错误和冲突入口。批量商品动作覆盖上架、下架、导出和高影响归档。

## 8. 表单、Drawer 与关闭保护

**FORM-01 — 统一业务容器。** 常规业务新增、编辑和详情统一使用 BusinessDrawer；危险短确认使用 Dialog/AlertDialog。复杂跨页面长流程可使用独立页面，通用规则不要求把完整工作台塞入抽屉。

**FORM-02 — 状态职责。** 字段值、是否修改和验证反馈属于当前表单草稿；远程选项、提交和记录新鲜度属于服务端状态。不能让一个全局 Store 同时保存所有页面未提交的表单数据。

**FORM-03 — 初始化。** 每次进入新增或编辑时建立明确基线；只读字段不能被普通表单值覆盖。异步详情或选项迟到时不应悄悄擦掉用户已经修改的字段。

**FORM-04 — 字段校验。** 必填、格式和依赖关系在前后端各自校验；首次 Blur 或提交显示错误，已有错误后随输入重验。提交时字段就近提示，顶部问题摘要将焦点引向首个可修正错误。唯一性检查在 Blur 后防抖执行，结果可能过期，保存接口仍是最终判断。

**FORM-05 — 服务端字段错误。** 422 等校验错误按字段路径回填，支持单条或多条消息；找不到对应字段的结构性问题放在表单顶部。定位首个错误后仍保留全部已输入内容，不仅弹出一个笼统失败 Toast。

**FORM-06 — 提交 Pending。** 进入提交态后阻止重复保存、取消和可能导致丢失上下文的关闭。业务可取消请求时才提供真正取消入口；视觉关闭不等于后端事务已撤销。

**FORM-07 — 全部关闭入口一致。** 右上角关闭、底部取消、遮罩、Esc、路由跳转和关闭 Tab 均进入同一关闭判断。不能只保护底部按钮，而允许遮罩点击直接丢弃草稿。

**FORM-08 — 未修改时关闭。** 无草稿改动且无 Pending 任务可直接关闭，返回发起位置并恢复合理焦点。查看详情不能无故出现“放弃修改”确认。

**FORM-09 — Dirty 关闭。** 有未保存修改时展示短确认，用户可继续编辑或确认放弃；未确认前保持原 Drawer 和输入。浏览器原生离开页面提示与应用内确认各有边界，不能承诺恢复未持久化草稿。

**FORM-10 — 保存成功与失败。** 默认取消/保存，成功后更新基线并关闭 Drawer；继续编辑等动作由 Recipe 显式开启。失败保留草稿与恢复动作，不能因列表刷新失败再次调用已成功的保存接口。

**FORM-11 — 冲突。** 409 在原 Drawer 内提供持久提示，可切换到差异比较并返回继续修改；保留草稿，不再嵌套 Drawer。版本号/ETag 等并发控制由端点契约规定，不默认强制覆盖或自动合并。

**FORM-12 — URL 与草稿。** 可分享详情使用受控 URL 标识；新增、编辑与密码等草稿不写入可恢复 URL。未授权或不在允许集合中的详情标识不能自动触发敏感请求。

**FORM-13 — 不嵌套业务抽屉。** Drawer 内轻量选择使用 Popover 等适用容器，危险确认使用 Dialog；禁止 Drawer 叠 Drawer。移动导航 Drawer 的宽度策略独立，不因业务编辑器全宽而一起全宽。

**FORM-14 — 组件组合边界。** BusinessDrawer 统一标题、内容、底部动作、关闭原因与异步保护；页面/Recipe 负责 Query、Mutation、验证和领域错误映射。通用容器不内置用户、角色或菜单接口。

**FORM-15 — 草稿适配器。** 默认不持久化表单草稿；长流程可通过显式、按身份隔离的安全适配器恢复。内容工作台可演示专属自动草稿并区分保存中、已保存、失败，不升级为所有表单的默认行为。

**FORM-16 — Step 与 Dynamic Form。** 步骤前进仅校验当前步骤及依赖，最终提交完整校验；允许非敏感步骤编号进入 URL，但恢复步骤不绕过前置条件。Dynamic Form V1 由前端类型化 Schema 定义字段、布局和规则，后端提供数据及选项；复杂字段经类型化组件/插槽扩展。未知类型或规则显示配置错误并阻止不完整提交，不静默降级或执行任意后端逻辑。

**FORM-24 — 草稿状态。** 输入停止 800ms 后自动保存，并在失焦或页面隐藏前尽力补充保存。远程草稿保存成功后清除本地未保存 Dirty，但“存在未发布修改”是独立状态；保存中或失败时离开必须拦截，不能把本地缓存描述为已远程保存。

**FORM-25 — Step 导航与凭证。** 已完成步骤可返回，未来步骤锁定，当前步骤通过校验后才可前进。最终创建成功后一次性展示 Client ID 与 Secret，支持复制并要求用户确认已妥善保存；Secret 不进入前端草稿，也不承诺再次完整回显。

**FORM-26 — 渠道配置。** 站内信配置标题、正文和跳转链接；邮件配置主题、发件人名称和模板/正文；短信配置签名、模板和变量；Webhook 配置地址、签名和超时。关闭渠道保留非敏感配置但不参与发送，敏感凭证不完整回显且重新启用时重新验证。渠道切换只切换同一表单模型的编辑面，不触发局部提交或确认；配置错误同时进入顶部摘要、渠道标记和可定位的行内错误，并阻止整体保存。

**FORM-27 — 状态与校验。** 09C 共用状态按验证、提交、草稿、冲突和结果组织，至少覆盖字段验证、Submitting、422、409、草稿恢复、自动保存失败、离线、权限撤回和成功。字段交互后在失焦时显示客户端错误；提交时显示全部错误、顶部摘要并聚焦首错。跨渠道摘要项必须能切换到对应渠道并聚焦可定位字段。

**FORM-29 — 冲突与权限变化。** 409 保留当前草稿并提供差异 Drawer，允许基于最新版本重新应用但不提供强制覆盖。编辑期间权限撤回应立即禁止提交并隐藏受保护的服务端内容；用户已输入草稿只允许在当前会话短暂保留，不能绕过重新授权恢复受保护投影。

## 9. 统一反馈与异常恢复

| 规则 | 触发情况 | 主要反馈与动作 |
| --- | --- | --- |
| STATE-01 | 首次无数据且请求中 | 匹配布局的 Skeleton 或局部 Loading；不出现空数据文案 |
| STATE-02 | 有数据且后台刷新 | 保留数据，局部刷新提示，防重复触发 |
| STATE-03 | 成功且集合为空 | Empty；仅有创建权限时提供创建动作 |
| STATE-04 | 成功但搜索无匹配 | Search Empty；保留条件，提供清空或修改筛选 |
| STATE-05 | 请求失败且无旧数据 | 主要区域内错误、合法重试与必要支持信息 |
| STATE-06 | 请求失败但有旧数据 | Stale 内容及持续恢复入口，不谎称最新 |
| STATE-07 | 浏览器离线 | Shell 全局 NetworkStatus；页面不重复多个离线条 |
| STATE-08 | 写入部分成功 | 持续结果明细、失败目标和限定范围的重试 |

**STATE-09 — 一个主要反馈面。** 同一失败由最接近业务上下文的区域负责，不同时弹 Toast、Dialog 和页面错误。只有结果不明显时才用短暂 Toast 补充，持续错误与恢复动作留在页面或表单中。

**STATE-10 — 取消请求。** 用户切换条件、离开或权限清理导致的取消不当作业务失败提示。是否取消成功以请求/事务契约为准，不能把取消界面操作描述为服务端数据已回滚。

**STATE-11 — 可用诊断信息。** 仅展示安全文案和确有来源的 Request ID，不显示堆栈、Token、内部主机名或原始后端对象。原型中的诊断标识不是业务数据，不能凭空伪造服务端 Request ID。

**STATE-12 — 状态按适用性组合。** 不要求每张页面都有所有状态：只读页没有批量写入就无需部分成功，局部接口失败不等同应用根级崩溃。完整分类参见 [页面状态与 URL 契约](../page-state-and-url-contract.md)。

## 10. 增强模块与非承诺范围

**EXT-01 — 核心与增强分离。** 认证、授权、布局、路由、核心管理和通用表单列表属于模板基础；SSO、多租户、PWA、监控和审计属于增强。仓库已经包含某个页面或 Mock，不自动使其成为默认启用的 V1 核心承诺。

**EXT-02 — 示例中心可关闭。** Form/Table/Chart/Upload/Draggable 等示例集中展示，配置关闭后不影响核心页面；四级以上导航和实验性能力只在示例中出现。组件库存未验收前不标记 Stable。

**EXT-03 — SSO。** 单 Provider 入口由安全配置决定，配置未确定前不展示有效登录入口；配置失败不阻塞密码登录。后端负责 OAuth/OIDC 事务、state/nonce/PKCE、账号映射和一次性应用票据交换，浏览器不接触提供方密钥或 Token。

**EXT-04 — 多租户。** 身份契约可包含后端确认的 `tenantId`，`null` 表示无租户归属的单租户会话；这不等于已交付租户管理、切换、计费或数据隔离产品。跨租户授权和缓存隔离须在真实后端验证。

**EXT-05 — PWA。** 依赖可保留但默认关闭；关闭时不生成或注册 Service Worker。即使启用，也不自动允许离线缓存受保护 API、密码、授权快照或敏感业务记录。

**EXT-06 — 监控与审计。** 可提供接入和页面 Demo，但生产监控口径、日志留存、审计防篡改及访问控制由真实后端承担。内存操作日志不是持久审计系统，不能作为生产合规证据。

**EXT-07 — 内容与工作台。** 表单工作台保留完整业务流程范例，内容管理保留内容场景；审计归于运维与审计职责。组件拆分或菜单重组不能悄悄删除这些已确认的演示范围。

**EXT-08 — 后端可替换。** 模板只承诺通用 API/OpenAPI 契约，`gnester-lite` 是接入示例。其基础设施或 Demo 不代表已有生产用户、角色、菜单、审计存储；关闭 Mock 前应逐项验证业务接口。

## 13. 接入后端前必须落定的政策

| 政策项 | 当前边界 | 谁提供最终答案 |
| --- | --- | --- |
| 密码长度、复杂度、历史和失效 | 不采用现有前端/Mock 常量作为统一生产政策 | 身份服务与业务方 |
| Captcha、限流与账号锁定 | 风险决定与 `retryAfter` 服务端权威 | 身份服务 |
| 注册验证、审核、初始角色和自动登录 | 注册默认关；开启后的分支仍需接入约定 | 身份服务与产品负责人 |
| Refresh Cookie、续期、撤销和跨站行为 | JavaScript 不读取 Refresh Token | 后端与部署负责人 |
| 多角色授权的传输与持久化 | 已确认 Allow-only 并集及按资源/操作合成；需落实多角色 DTO、三类版本、可授予投影和后端事务 | 授权服务 |
| 删除、软删除、保留和关联约束 | 明确保护与冲突，不默认级联或物理删除 | 相应领域服务 |
| 并发更新、幂等与结果未知后的重试 | 不提供通用前端覆盖或盲目重试 | 相应业务 API |
| 导出全量范围、异步任务、文件有效期 | 以真实端点能力为准，不把当前页当全量 | 数据服务与产品负责人 |
| 审计持久化、留存与租户隔离 | 均不由前端或 MSW 保证 | 后端与部署负责人 |

传输字段、状态码、分页、上传与运行时校验以 [API 契约](../api-contracts.md) 为准；前后端责任以 [安全契约](../security.md) 为准。历史文档中的已通过记录、Mock 数量或旧性能预算不能代替本次产品验收。
