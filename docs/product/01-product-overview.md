## 2. 产品定位

Gvueter 是可克隆、可直接二次开发的生产级 Vue Admin 基础模板，不是某个行业或企业的完整业务系统。

它同时服务两种使用方式：一是快速启动一个可运行的后台项目；二是在统一工程、权限、交互和组件规范上长期开发业务。模板中的用户、角色、菜单等页面既提供真实后台职责范例，也验证通用能力是否能够组合工作。

优先级固定为：**快速启动 > 工程实践 > 示例丰富度**。

这里的“生产级”是交付质量目标：边界明确、异常可恢复、可测试、可替换、可维护；不是对所有后端、部署环境和数据规模的无条件上线保证。

### 2.1 核心价值

1. 减少每个项目重复搭建认证、权限、路由、布局、请求和通用 CRUD 的工作。
2. 为团队提供一致的页面模式、数据生命周期和交互契约，降低协作成本。
3. 用完整范例展示正确的分页、错误恢复、权限变化和表单提交，而不只陈列外观组件。
4. 提供通用 API/OpenAPI 接入边界，允许替换后端服务和增强适配器。
5. 通过清晰的配置、依赖边界和示例隔离，允许项目裁剪而不破坏核心 Shell。

### 2.2 产品不承担的职责

- 不交付任何特定行业的完整业务模型、审批制度或合规结论。
- 不将 `gnester-lite` 作为唯一后端；它只承担接入示例角色。
- 不让前端权限控制替代后端授权、租户隔离或数据范围计算。
- 不在 V1 交付命令式项目生成器；V1 使用完整仓库克隆方式。
- 不默认承诺多租户运营平台、可观测服务端、审计存储系统或生产 SSO 服务。
- 不以“库已安装”作为功能开放、组件稳定或完整测试的证据。

## 4. V1 范围分层

### 4.1 核心基础能力

| 能力域 | V1 目标范围 | 边界 |
| --- | --- | --- |
| 账号与会话 | 登录、退出、忘记密码、重置密码、Token 管理 | 注册可选且默认关闭；续期须有真实后端契约 |
| 权限 | 路由、菜单、按钮与数据范围 | 角色是主要分配入口；前端仅负责体验控制 |
| 导航 | 动态路由、多级菜单、Breadcrumb、页面搜索 | 授权后的导航一致；正式层级不超过三级 |
| 工作区 | Tabs、KeepAlive、布局切换、头像菜单 | 页面缓存与服务端 Query Cache 分离 |
| 外观 | Light/Dark/跟随系统、受控品牌、国际化、响应式 | PC 大屏优先，同时保证移动端可达 |
| 请求 | Axios 封装、统一错误、网络异常、Loading、Mock | 错误标准化与用户提示分工明确 |
| 数据操作 | DataTable、SearchForm、Form、业务 Drawer | 配置化复用重复逻辑；保留组合与插槽扩展 |
| 公共交互 | 全局/局部全屏、Chart、Draggable、Custom Directives | 具体场景按需启用，不默认扩展到所有页面 |
| 系统边界 | 403、404、500 及局部失败恢复 | 系统页面独立可达，不进入常驻业务菜单 |

以上完整覆盖初始需求中的注册、认证、Token、权限、动态多级导航、缓存、全屏、主题、国际化、搜索、头像、错误处理、骨架屏、请求封装、Mock、多布局、拖拽、图表和指令。

### 4.2 核心业务范例

- **Dashboard**：默认首页，验证模块组合、图表、权限投影和独立异步状态。
- **用户管理**：验证查询、分页、创建/编辑、角色关联和危险操作。
- **角色管理**：验证角色列表、三 Tab 授权 Drawer、页面/操作授权树与数据范围。
- **菜单管理**：验证目录、页面、外链、iframe、动态路由与导航同步。
- **表单工作台**：验证多步骤、字段联动、提交与失败恢复等完整流程。
- **内容管理**：保留内容场景的范例职责；审计能力统一归入运维与审计，不用占位页重复职责。

不设置独立 Permission Management 常驻页面。权限配置集中在 Role Drawer，角色关联只在 User Drawer 编辑。V1 采用多角色、Allow-only RBAC，不提供 Deny、用户级权限覆盖和角色继承；有效数据范围按同一资源/操作实际获授权的角色合成。Q1070–Q1146 已确认的生命周期、可授予边界、三类版本与失败恢复详见[业务规则第 3 节](./02-business-rules.md#3-角色权限与数据范围)。

### 4.3 示例中心

示例中心集中管理，并应支持项目配置整体关闭。仅隐藏菜单不算关闭完成；相应入口、搜索结果、路由和依赖边界也必须符合配置契约。

| 示例族 | 内容范围 | 对二次开发的价值 |
| --- | --- | --- |
| Form | Basic Form、Search Form、Step Form、动态与复杂表单 | 学习校验、联动、草稿和提交组合 |
| Table | Basic Table、Tree Table、Complex Table、虚拟滚动 | 学习数据模式、分页、树展开和性能边界 |
| Data Display | Chart、Detail、状态标签、指标、时间线 | 学习信息表达和无数据处理 |
| Overlay / CRUD | Dialog、Drawer、完整 CRUD 场景 | 学习选择合适容器及关闭保护 |
| Operations | Upload、Draggable、导入导出等 | 学习长任务、进度、校验与部分失败 |
| Feedback | Error Log、加载、空、失败、离线 | 学习异常分类、提示归属和恢复动作 |

“Draggable 示例”不等于菜单管理或 Dashboard 默认支持任意拖拽重排。菜单 V1 通过既定排序字段维护，Dashboard V1 不提供用户拖拽布局持久化。

上游库存组件与稳定业务组件区分管理。Carousel、InputOTP 等即使保留依赖和源码，也要具备 Demo、文档、测试及真实消费证据后才能开放为稳定能力。

### 4.4 增强能力与未来能力

| 能力 | 产品归类 | 接入要求 |
| --- | --- | --- |
| SSO | 增强 | 服务端配置 Provider、授权回调、一次性凭据交换与退出契约 |
| 多租户 | 增强/后续接入 | 后端身份绑定、数据隔离、切换与缓存清理，不以 `tenantId` 字段存在判定完成 |
| PWA | 增强，目标默认关闭 | 显式启用、更新提示、离线边界与构建/Service Worker 隔离 |
| 监控与审计 | 增强 | 对接真实数据源、权限、脱敏和后端留存策略 |
| 项目生成器 | V1 之后 | 基于稳定模块边界裁剪和生成，不影响当前克隆交付 |
| RTL | V1 不承诺 | 本轮先完成中英文和核心可访问性 |

仓库已存在部门、岗位、字典、系统配置、系统参数、通知等模块。这些是可复用的现有范例或扩展模块，不因源码存在而自动扩大初始核心页面的交付承诺；是否随具体项目启用，应写入项目配置清单。

核心导航按真实后台职责组织；组件类型只出现在示例中心。

```text
工作概览（一级页面，默认首页）
系统管理
├── 用户管理
├── 角色管理 / 授权 Drawer
└── 菜单管理
运营
├── 表单工作台
├── 内容管理
└── 运维与审计（增强能力）
    ├── 监控
    └── 审计日志

├── Form
├── Table
├── Chart / Detail
├── Dialog / Drawer / CRUD
└── Upload / Draggable / Error Log 等
```

这是产品职责树，不是要求每个项目展示全部菜单。实际导航是“已启用模块 ∩ 当前身份可访问内容”的投影；原型中的运营、访问分析、系统健康等精简条目用于演示这一投影，不要求将所有示例一起塞进侧栏。

- 登录、找回密码、重置密码、可选注册、SSO Callback 和 403/404/500 是流程或系统节点，不占据常驻导航。
- 详情等隐藏页面可以通过业务入口访问；有合法参数且有权限时，可按搜索契约收录。
- Dashboard 为默认落点；角色首页或上次访问页面是扩展点，不能擅自更改默认行为。
- 用户/角色/菜单是权限 Demo 的核心；更深菜单只在能力 Demo 中出现。
- 视觉标签、导航位置、菜单 ID、权限标识与路由地址属于不同概念，调整侧栏展示不等于迁移 URL。

## 6. 核心使用流程

### 6.1 开发团队快速启动

1. 克隆仓库，使用仓库要求的 Node.js 与固定 pnpm 版本安装依赖。
2. 选择 Mock 演示或真实 API 环境；先跑通认证、授权、菜单和默认 Dashboard。
3. 替换品牌、文案、模块启用清单及后端配置；保留生产安全边界。
4. 参考用户管理或表单工作台添加一个真实业务模块，复用查询、表单和反馈契约。
5. 使用符合 OpenAPI/运行时 Schema 的后端替代 MSW，不让页面承担传输层兼容代码。
6. 执行测试、生产构建、契约与安全检查，再完成部署环境验收。

具体命令和真实环境变量见 [技术开发](./03-technical-development.md)。尚未落地的目标开关不伪造为可用环境变量。

### 6.2 后台操作人员登录与工作

```text
登录提交
  → 建立会话
  → 加载身份、授权与安全导航
  → 校验回跳地址
  → 进入默认或合法目标页
  → 搜索 / 菜单 / Tabs 切换任务
  → 查询、编辑、提交与结果反馈
```

身份或权限变化会影响多个下游：导航、可见操作、页面可达性、受保护 Query Cache 和实时连接必须同步处理。任一旧请求返回都不能重新写入已失效身份的数据。

### 6.3 数据维护闭环

搜索条件先形成有效查询；分页、排序与选择遵循明确规则。创建/编辑/详情默认进入业务 Drawer；成功后更新相关查询，不刷新无关模块；失败时保留必要上下文并提供可执行恢复动作。

删除、权限更新等高影响操作需要范围说明和确认。前端展示确认不意味着后端已经接受操作，最终结果以服务端响应及随后读取的一致状态为准。

## 7. 产品级设计原则

### 7.1 视觉与交互

- 采用现代 SaaS Admin 的 Quiet Layers 方向：留白、排版、弱分隔建立层级。
- 默认品牌使用 Tailwind Violet；Light/Dark 与受控品牌切换共享语义 Token。
- 不使用厚重侧栏、Header 卡片化或“所有内容装进 Card”的页面模板。
- PC 以 1440px 为设计基准，并验证 1920/2560 宽屏；扩展宽度优先转化为合理留白和工作空间。
- 全部后台页面使用一致的导航母版，包括仍标为 Archive 的三张历史探索稿；其主体视觉不作为正式主题备选。
- 状态插图采用透明背景的主题化矢量，不以白色底板包裹 Empty；Not Found 是当前六类插图的风格参照。

### 7.2 组件与状态

- 业务增强表格只保留一个公开入口 DataTable；高级能力采用模块化、可选插件方式演进。
- 轻量静态 Table 继续存在，避免简单展示承担服务端查询和表格引擎成本。
- SearchForm、DataTable、Form 与 Drawer 独立组合。更高层 CRUD 组合需有清晰职责，不能成为难以拆开的全能页面组件。
- 服务端状态归 Vue Query，跨页面客户端状态归 Pinia；输入草稿和浮层开关归局部状态。
- Skeleton、Refreshing、Empty、Error、Offline、Forbidden 分别表达不同事实，不互相替代。
- 页面、组件与请求层之间确定唯一主要反馈归属，避免同一失败连续弹出多个提示。

| 安全 | 后端独立授权；敏感数据不进入 URL、日志或非必要持久存储 | 前端安全测试 + 真实后端/部署环境测试 |
| 可靠性 | 错误、取消、竞态、会话失效和重复提交均有处理 | 故障注入、组件测试、端到端流程 |
| 性能 | 重型能力按需加载，缓存有上限，大表和树有可验证策略 | Bundle 门禁、性能契约与浏览器实测 |
| 浏览器 | 最近两个版本的 Chrome、Edge、Firefox、Safari | 发布时固定具体版本清单；引擎测试不等于真实设备全覆盖 |
| 响应式 | 桌面、大屏及移动端任务可达，无非预期遮挡 | 多宽度页面矩阵、实际交互及截图检查 |
| 国际化 | 中文/英文、长文本、日期数字与时区显示一致 | 键集合、文案膨胀、格式化与页面回归 |
| 可访问性 | 键盘可达、焦点可见、状态可感知、减少动效可用 | 自动语义检查 + 人工关键流程检查 |
| 可替换性 | 后端、品牌、图表及增强适配器有边界 | 替换代表性模块并跑通消费契约 |

不在总览中承诺未经测量的并发量、页面响应时间、服务可用率或安全认证。当前工程性能预算是仓库配置事实，详见[性能文档](../performance.md)；生产指标还需固定设备、网络、数据规模和测量口径。

### 10.1 组件成熟度

- **Candidate**：规格和初始实现/原型可以评审，尚有场景未验证。
- **Validated**：至少在一个真实核心页面中消费，相关状态、适配和行为已验证。
- **Stable**：API、文档、测试及迁移边界稳定，满足作为模板公共能力的交付要求。
- **Legacy / 库存**：保留参考或迁移用途，不应被新页面当作稳定入口使用。

## 11. V1 发布验收

### 11.1 必须闭环的用户结果

1. 新项目能够按说明启动，明确使用 Mock 还是真实后端。
2. 登录、授权初始化、动态导航和默认首页形成闭环；退出后受保护状态被清理。
3. 用户、角色、菜单能够完成代表性查询与维护，并验证拒绝、冲突及失败恢复。
4. 业务列表和表单能够用统一组件组合，新页面不复制分页、错误和提交控制逻辑。
5. 主题、中英文、主要响应式宽度及关键键盘操作符合统一规范。
6. 示例中心和增强能力可按约定关闭，不留下无效导航、注册入口或运行副作用。
7. API/OpenAPI 与运行时 Schema 一致，真实后端关键流程完成集成验证。
8. 当前版本约定的类型、Lint、测试、构建、契约、安全和产物门禁通过。

### 11.2 发布证据

发布记录至少包含：代码版本、锁文件、环境类型、具体浏览器/视口、执行命令、结果、截图或测试产物、已知限制及未闭环事项。存量截图和历史通过记录可以引用，但须注明版本和日期。

产品文档检查与静态原型 QA 不替代业务重构、后端联调、全量浏览器验收或正式发布。
