# DOM 指令能力决策

本项目不以指令数量作为完整度指标。指令只适合直接拥有某个元素的底层 DOM 生命周期；权限、请求状态和业务交互继续由响应式组件或 composable 管理。

| 候选指令           | 结论   | 现有权威能力                                              | 生命周期、键盘与无障碍原因                                                                       |
| ------------------ | ------ | --------------------------------------------------------- | ------------------------------------------------------------------------------------------------ |
| `v-permission`     | 不适用 | `PermissionGate`、CASL、路由守卫和服务端鉴权              | 组件能响应权限更新并保留清晰的渲染边界；直接移除 DOM 不能替代服务端授权，也容易丢失焦点。        |
| `v-copy`           | 不适用 | `CopyButton`                                              | 按钮拥有支持检测、成功/失败反馈、可读名称和键盘激活；指令无法可靠提供这些可见状态。              |
| `v-debounce-click` | 不适用 | mutation pending 状态、禁用按钮、`watchDebounced`         | 写操作必须显式防重复并展示 pending；搜索防抖属于请求 composable，卸载时取消旧请求。              |
| `v-long-press`     | 不适用 | 可见 Button / DropdownMenu 操作                           | 长按不易发现，也没有统一键盘等价操作；后台关键动作始终使用可见触发器。                           |
| `v-autofocus`      | 不适用 | 原生 `autofocus`、VeeValidate 首错聚焦、Reka 浮层焦点管理 | 路由和浮层需要按上下文决定焦点；通用挂载聚焦会抢走用户当前焦点。                                 |
| `v-click-outside`  | 不适用 | Reka Dialog、Popover、DropdownMenu、Sheet                 | 上游 primitive 已处理 Portal、Escape、外部交互、焦点返回和卸载清理，禁止再注册第二套全局监听器。 |
| `v-throttle`       | 不适用 | ResizeObserver、虚拟滚动器和组件内事件策略                | 当前没有必须由裸 DOM 高频事件驱动的业务场景；出现真实场景时再以可测的帧预算复评。                |

水印与 Loading 继续由 `AdminWatermark`、`AsyncState` 和组件的 `isLoading` 契约负责，不创建同职责指令。

## 复评门槛

只有同时满足以下条件才新增指令：能力必须直接绑定单一 DOM 元素；现有 primitive、组件或 composable 无法表达；键盘等价操作、可读名称、挂载更新卸载清理和单元测试均已定义。新增前还需给出真实消费页面，不能只提供孤立 Demo。
